# Slice 08: Controlled Diagnosis and Transition

## Purpose

Exhaust offline discrimination, run only the smallest sequential live manifests needed to identify one causal readiness boundary, challenge the conclusion, and enter Block 4 only after a clean audited exit.

## Design

Every experiment follows:

```text
offline hypothesis update
→ new frozen manifest/case identities
→ independent manifest audit
→ checkpointed live execution
→ immutable terminal/evidence audit
→ Captain Progress Report update
→ root threshold or next one-factor discriminator
```

E0 measures local stage timing, schema-projection/backend-validator parity, response bounds, input/wire size, repair payload duplication, and lifecycle durability. E1 runs the new Activity case at high effort with at most `readiness` plus natural `readiness_response_repair`. E2 uses the same exact case at medium only if provider/control remains plausible. Later input-size, bound, or repair-shape experiments require direct evidence and new audited manifests.

Apply the active thresholds to the complete ledger. Select one of `focused_implementation_correction`, `readiness_component_redesign`, `provider_control_response`, or `additional_evidence`. Semantic quality beyond mechanical/provider evidence remains unclaimed unless independently supported; missing human judgment does not invalidate mechanical conclusions.

Before Block 4, `.devin/captain-progress-report.md` records experiments, calls used/remaining, root evidence, alternatives, proposed correction, risks, rollback, and verification. An independent exit audit must find no critical/high/medium issue.

## Execution Contract

- **Depends on / inputs:** committed S07 cleanup, clean exact HEAD, remaining budget, zero pre-existing active identities, current hypotheses, and corrected v1 contracts/command.
- **Outputs:** E0 evidence; immutable manifest/run artifacts; safe result JSON/Markdown; exact call ledger; one recommendation or exact next discriminator; Captain report; Block 3 Outcome/current-state; conditional Block 4 boundary.
- **Exclusive write ownership:** new `.graphpilot/evaluation/readiness-diagnosis/` identities, Block 3 result evidence, this Outcome/group/status, ignored progress/state files; Block 4 plan only after exit pass.
- **Forbidden/shared ownership:** unsupported correction, generation/semantic review, calibration/certification/promotion, Block 2, `.env`, S15, Stage C.
- **Resources:** sequential Azure calls only after each manifest audit; no concurrent manifest or favorable rerun.
- **Cancellation:** missing credentials/permissions, unterminalizable uncertainty, material audit/security conflict, exhausted budget, destructive work, unapproved dependency, or final promotion decision.

## Included Work

- Produce E0 machine/Markdown evidence and independently audit its conclusions.
- Freeze and audit each manifest with one hypothesis, exact assets/controls/roles/order/IDs/ceiling, budget, rollback, scope, and no-rerun policy.
- Execute each manifest once, terminalize, verify safe metadata/validation/capture closure, and account every started or uncertain call.
- Update hypotheses, weekend state, and Captain Progress Report after every experiment.
- Continue only with the next smallest causal discriminator while multiple roots remain plausible.
- Reconcile every hypothesis with supporting/disconfirming evidence and define the narrowest correction, consumers/contracts, risks, proof, and rollback.
- Run independent Block 3 exit audit and correct every material finding.
- Commit Block 3 evidence/handoff.
- Automatically create, audit, and commit the Block 4 plan after a clean exit; implement only within that audited correction boundary.

## Not In Scope

Semantic certification, generalized experiment framework, human-label gate, generation/review calls, representative quality or promotion claims, S15, Stage C, or correction implementation before Block 4 plan/audit.

## Exit Criteria

- Every started or uncertain call is counted and terminalized.
- No checkpointed/terminal identity reruns.
- Exact validation trigger, time domains, payload duplication, controls, and evidence limits are recorded when available.
- Exactly one root threshold passes and alternatives are disconfirmed, or the exact next evidence need remains explicit.
- Every manifest/result audit has no unresolved material finding.
- Captain Progress Report is current before Block 4.
- Independent exit audit has no unresolved critical/high/medium finding.
- Block 4 owns only the evidenced correction.
