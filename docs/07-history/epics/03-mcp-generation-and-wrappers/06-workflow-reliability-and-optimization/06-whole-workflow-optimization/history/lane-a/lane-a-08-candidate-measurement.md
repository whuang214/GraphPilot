# Lane A Slice 08: Candidate Measurement

## Purpose

Capture strict new-identity candidate Todo C1/W1 observations and provider-free I1, then execute one live I1 only if separately authorized after Lane B releases provider resources.

## Design

Use the same frozen request, Todo commit, Copilot host/model/new-chat procedure, recorder version, and declared cache/index evidence as the compatible baseline cells. The intentional treatment is the committed Lane A host/snapshot candidate. C/W stop after durable JSON 2 save and make zero Azure calls.

## Included Work

- Freeze new C1/W1/I1 manifests and verify unused identities, exact source/GraphPilot commits, assets, procedure, and starting states.
- Run human C1 from missing JSON 1/JSON 2 and human W1 from complete current JSON 1 with no coaching.
- Capture Stage 2 lookup cost inside complete host wall.
- Record machine wall/MCP/attempt/failure/artifact evidence and post-save host summaries.
- Verify W1 performs zero broad source search, zero source reads, and zero JSON 1 writes.
- Execute provider-free I1 through real MCP/fake provider/browser and the complete guard.
- Prepare and path-audit a short-identity live I1 package only after provider-free pass.
- Dispatch live I1 once only after separate explicit user authorization and Lane B provider-resource release.
- Independently audit terminal evidence, quality, security, compatibility, resources, and no-rerun.

## Not In Scope

- Code/docs changes after manifest freeze, retries, old identity reuse, provider concurrency, next-wave implementation, cross-cell percentages, generalized repos/types, promotion, or certification.

## Target Areas

- Todo fixture new candidate host-benchmark identities.
- A01 benchmark control storage and provider-free/live I1 packages.
- This Outcome and measurement-only Lane A handoff inputs.

## Exit Criteria

- C1/W1 are complete valid new-identity zero-Azure observations with successful durable request save.
- Each candidate cell matches its baseline control key except the intentional Lane A treatment and new runtime identities.
- Validation failures, authoring attempts, searches/reads, source bytes, JSON sizes/tokens, and complete wall are exact or explicitly labeled host-reported/derived/unavailable.
- Provider-free I1 passes readiness/generation/quality/grounding/persistence/SVG/browser/recovery guards.
- Live I1, when authorized, is one terminal attempt with exact budget and no overlap with Lane B.
- No evidence is mutated and no terminal identity reruns.
