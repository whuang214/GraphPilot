# Lane A Slice 07: Lane A Integration

## Purpose

Integrate the committed snapshot backend and host interface through the shared MCP/schema/diagram/documentation boundaries and prove the complete candidate provider-free before external measurement.

## Design

The integration owner wires the new contracts atomically, resolves only integration-owned conflicts, preserves Lane B behavior, updates canonical generation-time grounding metadata, and runs the complete offline guard. No candidate measurement or provider call occurs in this slice.

## Included Work

- Schema/contract identity registration and shared service construction.
- Public MCP registration/removal for the structured route tool, authoring lookup, snapshot evidence tools, durable request save, and generation consumption.
- Active removal of the old workflow prompt surface without a compatibility alias.
- Canonical generation-time grounding receipt and frontend type/adapter preservation.
- Direct/context request/result/error/recovery integration.
- Canonical owner and navigation updates, decision log, Lane A group/Outcomes, and current-state update where status changes.
- Full provider-free generation/readiness/semantic/layout/persistence/render/browser guard.
- StdIO smoke, contract/example/leakage, path/security, recovery/no-rerun, and instrumentation-equivalence checks.
- Independent combined diff audit and correction.

## Not In Scope

- C1/W1/I1 execution, live provider calls, Lane B contract changes, next-wave implementation, representative validation, promotion, or certification.

## Target Areas

- Shared schema registry and contract identity registration.
- `backend/mcp_server/server.py` and MCP smoke tests.
- Canonical diagram schema plus frontend type/adapter parity as required.
- Canonical MCP/context/generation/workflow-audit owners and decision/navigation/status files.
- Cross-lane integration tests only; A04/A05 exclusive files are changed only to resolve verified integration defects.

## Exit Criteria

- All new public tools expose exact strict inputs/results and no retired prompt/old host surface remains active.
- Direct and context provider-free workflows save valid requests and produce valid generated/blocked/error behavior through real stdio.
- Snapshot replacement, stale request rejection, finalization, timeout recovery, generation-time grounding, SVG, and editor identity pass.
- Instrumented/uninstrumented production behavior remains equivalent outside the intentional host/snapshot contract change.
- Lane B provider contracts, code, evidence, identities, and current guard behavior remain unchanged.
- Complete backend and frontend required gates, smoke, browser, link, security, and independent implementation audit pass before commit.
