# Block 5: Complete Live Anchor and Re-Audit

## Goal

Prove one genuinely ready repository-grounded request from user intent through a correct visible editable diagram, then rerun
the complete Block 1 audit method now that every downstream live stage can be reached.

## Why It Follows Readiness Proof

S13–S15 measured only live readiness because attempts stopped before generation. Block 5 is the first point where readiness,
generation, deterministic repair, semantic review/repair/final review, layout, persistence, rendering, MCP return, and editor
completion can be measured as one provider-backed critical path.

## Question This Block Owns

Can the complete live workflow produce one correct grounded diagram without hidden retry, and what is the exact current
request-to-visible-editor critical path that Block 6 should optimize?

## Anchor Workflow

Use one newly identified, human-reviewed, genuinely ready request. The measurement begins at the host user request and covers:

1. host routing, source discovery/reads, and JSON 1/JSON 2 authoring/reconciliation;
2. MCP process/discovery/transport and tool operations;
3. mandatory final readiness and any naturally reached bounded repair;
4. fixed-example/packet construction and strict logical generation;
5. deterministic validation and repair when reached;
6. semantic review, response/candidate repair, and mandatory final review;
7. PyGraphviz, canonical assembly, provenance, context stability, persistence, and SVG rendering;
8. result serialization, editor-link return, API load, browser errors, and visible completion.

All calls use a frozen exact schedule, role ceilings, stop rules, and separately approved live budget. Timeout/lost-response
recovery never reruns an identity.

## Implementation Slice Plan

The anchor approval, live harness, execution, and re-audit slices live in [`05-complete-live-anchor-and-reaudit/00-group.md`](05-complete-live-anchor-and-reaudit/00-group.md). The nested group owns sequencing and Outcomes; this block owner retains the complete-anchor and Block 6 gate.

## Quality Gate

The anchor succeeds only when reviewed required meaning is present, material unsupported meaning is absent, canonical schema
and provenance are valid, reviewed semantic quality passes, persistence/rendering succeeds or yields an allowed recoverable
warning, and the editor visibly loads the exact owned diagram without material error.

A blocked, failed, or interrupted result is durable evidence but does not establish the complete live anchor. Diagnose and
correct the failed downstream owner before rerunning through a newly approved policy; do not broaden coverage.

## Re-Audit

After the anchor succeeds, rerun Block 1's complete audit against the exact current workflow and asset versions. This audit
adds the previously missing live generation/review path, reconciles host/provider/MCP/local/browser contributions, identifies
natural repairs and cache behavior, and creates the versioned optimization baseline.

## Outputs

- One complete provider-backed diagram and editor proof.
- Complete non-overlapping user-visible wall time and nested stage/role evidence.
- Host reads/tokens/credits, Azure roles/tokens/durations, MCP transport, local stages, and browser timing.
- Quality/provenance/recovery result.
- Rerun Block 1 report and ranked Block 6 optimization backlog.
- Anchor scenario and baseline identity retained as the optimization guard.

## Exit Gate

Block 5 completes only after one correct visible live diagram, complete evidence with no unknown critical-path gap, a rerun
Block 1 report, and a ranked optimization backlog whose recommendations follow measured contribution rather than ease.

## Not Owned Here

- Representative type/status/stability claims.
- Multiple unrelated optimization changes.
- Runtime/prompt/configuration promotion.
- Certification.

## Block-Agent Handoff

The agent returns the exact anchor package, live budget/actuals, complete critical path, quality artifacts, recovery evidence,
Block 1 rerun report, ranked opportunities, checks/commits, and any downstream issue that must be corrected before Block 6.
